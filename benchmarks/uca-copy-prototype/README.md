# Issue154: private-copy UCA source prototype

2026-11-11. **The original contraction producer and the prepared-copy proposal
match all 918,588 payload bytes across three levels.** The minimum experimental
patch is assembled and applies after the canonical UCA patch with zero fuzz.
This is `PASS_SOURCE_ONLY`: no new guest, SQL/native server comparison, two-child
runtime test or performance measurement has run. The proposal is not adopted.

[Issue154](https://github.com/masahitojp/mariamem/issues/154) own the boundary.
Runtime baseline is `500020e7dc6d702ef059f0e73a4bab738103b774`; the source audit
base is `8a5525669679dfd5fc8c3b6f5a80dd26198eacbf`. `inputs.json` pins every
upstream file to MariaDB `83e909fc2a0dbc394b4b683fb3fa2d7dcf26cc5e`.

## What was executed

- Run the pinned, unchanged `uca-dump.c` with the original implicit-weight helper
  bodies and pinned Unicode14 input. It emits 939 contractions per level.
- Compile nine original contraction producer/helper definitions unchanged.
  The reference uses the original built-in list construction loop and original
  hash allocation/population, not the new algorithm as its own oracle.
- Independently construct numeric flags/hash data in Python, then compare all
  original list/flag/hash bytes, including padding, against that representation.
- Compile the exact proposed `copy.c` against the generated C data and compare
  every byte for five allowed identities times three levels. Check allocated
  pointers differ from source/prepared arrays and other modeled destinations.
- Deliberately mutate one destination's list/flags/hash; another destination
  remains equal to the reference (three level cases).
- Inject failure at each of three allocations: return failure, do not publish
  payload pointers/counts, and leave partial allocations tracked for disposal.
- Check nine eligibility misses without allocating: another ID, NULL/changed
  tailoring, rules present, different source/destination, level, maxchar/count.
- Run independent original-producer verification mode for all 15 combinations.
- Reject deliberately corrupted flags/hash via full-byte checks and wrong layout
  via compilation. Reject changed Unicode source identity before compiling.

The test is a small native C harness with explicit **WASM32 scalar** types,
60-byte contraction layout, and native pointers/allocator. Minimal dependency
headers supply types/macros; the generator and extracted producer function
bodies are unchanged and hashed. It is not an ordinary native MariaDB build,
actual WASM execution or proof of complete guest ABI equivalence. The callers,
loader and descriptors are modeled where stated; their whole runtime integration
remains unverified. `result.json` records compiler, hashes, results and limits.

## Experimental patch and failure prerequisite

`guest/experimental.patch` adds the guarded private-copy path after original page
preparation, then returns to the original booster path. It includes generated
**source input**, not CI output: a typed static hash/flag header. Its numeric size
is 749,568 bytes; the patch text is about 217 KB. `make_patch.py` deterministically
recreates it. The sparse C initializers avoid thousands of explicitly zero cells;
no runtime decoder or pointer-bearing snapshot is introduced. Canonical
`guest/source.patch`, generated runtime, public APIs and release data are unchanged.

Connecting the failure path exposed two existing problems in the pinned callers:

1. `create_tailoring` leaves `rc=0` when the shared UCA initializer returns NULL,
   on both the default UCA1400 and MySQL-alias branches.
2. The shared initializer uses `level[0].weights` as readiness. An initialization
   failure after writing it can let a later attempt skip initialization.

`caller.c` compiles the **exact original two callers**, with a stub level
initializer that writes the sentinel and fails. Both original false-success
and skipped retry reproduce. The experimental correction clears the partial
UCA descriptor on failure (arena buffers remain owned) and sets the caller
error code before exit. The same harness then observes error propagation and
actual reinitialization on retry on both routes. These are controlled source-level
faults, not an observed production OOM or a guest-admission PASS.

This prerequisite is kept as visibly separate hunks generated by `failure_fix.py`.
Its correctness value is separate from the copy path's unmeasured speed. It does
not change successful initialization, allocator ownership, cache keys or Close.
Real-guest fault handling and alias/variant order tests remain required before
claiming the failure contract is satisfied in the product.

## Reproduce

Acquire files listed by `inputs.json` from that exact MariaDB commit into a
scratch `source/` directory, using each basename. For GitHub contents larger than
1 MiB, acquire the named Git blob and base64-decode its JSON content; reject any
SHA256 mismatch. Use `scripts/git_identity.py` for the repository source commit
before a build. In a disposable experiment workspace:

```sh
python3 benchmarks/uca-copy-prototype/source_check.py --source /path/to/source --out /path/to/scratch/check
python3 benchmarks/uca-copy-prototype/make_patch.py --source /path/to/source --check-output /path/to/scratch/check --output /path/to/scratch/experimental.patch
```

The source check needs a C11 compiler and Python, not a server, Go build or guest
toolchain. It recompiles negative controls and checks the original/fixed callers.
The patch generator checks the producer receipt/header, applies the canonical
UCA portion, and tests the new patch with `--fuzz=0`. Compare the patch/header hashes
with `result.json`. Do not relabel this native receipt as a platform/guest gate.
Fresh repeat output belongs to scratch, not this record.

Only scripts, candidate source, pins and compact receipt/checksums are retained.
The full upstream sources, generated upstream header, native binaries, raw payload
and compiler output are recreatable and are deleted after verification.
