# T4　試作候補と短縮余地

**保留する候補は、SUM の注文 UPDATE が計画情報を保存する際のゲスト割り当て。** 位置は `Update_plan::save_explain_data_intern`（Fn14079）から `String_list::append_str`（Fn20087）を通って `dlmalloc`（Fn152）に到達する経路。固定ソースの `internal/generatedgo/code/p1/p1_pure.go` 11788 行に対応する arm64 命令は、イメージ相対 `0x773bbc` の `MOVW R4, (R5)(R0)`。境界チェックを呼び出した後の 4 バイト書き込みに標本が集中した。[PC と呼び出し元別の集計](allocator-site.csv) · [逆アセンブル](allocator-store.asm)

| 組 | SUM の trigger 中の全標本 | 当該命令の trigger 標本 | そのうち計画保存経路 | 計画保存経路の CPU ms/100 INSERT（A / B / C） | 全 SQL の A−B CPU ms/100 INSERT |
|---|---:|---:|---:|---|---:|
| 1 | 356 | 320 | 252 | 1.017 / 0 / 0 | 0.867 |
| 2 | 366 | 322 | 254 | 1.030 / 0 / 0 | 0.704 |
| 3 | 349 | 303 | 231 | 0.934 / 0 / 0 | 0.867 |

この経路・命令に観測された **0.93〜1.03 CPU ms/100 INSERT** は、その費用をすべて除ける仮定での標本上の上限。変更後の実際の CPU 削減量、経過時間の短縮量は未推定。局所差が SQL 全体の対応差を超える組がある。他経路の逆向きの差と標本変動を含むため、差分率を実現できる利益として扱えない。
