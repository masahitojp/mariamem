# 保守間隔を分けた候補の再生成と 8 DB 同時復帰

**既定化は保留する。** 候補は再生成でき、全 72 波・576 件の同時復帰で各 SQL が成功した。一方、分離案の 1 DB で、稼働中 50 ms の通常モードのまま最後の保守コールバック進入から 126.45 秒が経過した。保守処理は P8 でワーカーの補充を担っていたため、軽い問い合わせへの応答だけでは、この途切れが運用上無害とは判断できない。

## 1 DB で保守の記録が途切れた

分離案の第 3 試行、6 番目の fork（内部のプール ID 7）。各波の開始直前に、最後に Fn16626 に入ってからの経過を同じプールで読んだ。第 1 波は 43.6 ms、第 2 波は 6.16 秒で、その後は 14.16、22.17、30.17、38.18、46.19、54.19、126.45 秒と増えた。全 9 回とも通常モード。最後の同時復帰でこの DB 自身の要求はバリア開放から 3.95 ms で完了し、最終在庫・注文の検算も通った。他の分離案 31 DB の通常モードでの観測最大は 50.05 ms 未満、現行 32 DB は 398.60 ms 未満だった。保守回数の集計にもこの試行を含めた。[各DBの最大経過](timer-ages.csv) · [全要求の時系列](requests.csv)

記録点はコールバックの進入である。コールバックが戻らなくなった、次のタイマーが発火または配送されなくなった、プールへの計測の対応付けが変わったという可能性を区別するには追加の記録がいる。今回の 1 件だけでは分離案固有の現象かも決められない。次の判断には、同じ現行・分離の 8 DB シナリオにプール識別、タイマーの再設定・発火、タスクの登録と取得、コールバックの進入と退出の時刻を足す。異常 1 件を対応付けるか、今回と同じ 4 組（本計測約 18 分、ビルド別）で打ち切る比較を推奨する。

## 候補の実装と再生成の確認

候補はリング a1ce4a7d を基点とする fa7d878d0bdc8616726db0e8a822285f987a2e91。稼働中の間隔を 50 ms とし、低頻度モードの 2 種類のタイマー書き込みに 4 秒を指定する。MariaDB ソースや公開設定への変更はない。生成器は対象 guest と入力 2 ファイルの SHA-256 を確認し、対象関数内の代入箇所数を検査してから変換する。[候補の差分](https://github.com/masahitojp/mariamem/compare/a1ce4a7d568fbf6eac7bee032a7fdfbe464544fb...fa7d878d0bdc8616726db0e8a822285f987a2e91)

固定リングの生成 Go を Git から別々に取り出し、2 回とも生成結果が候補とバイト単位で一致した。初回の検査で静的イメージに旧ソースのハッシュが残ることを検出したため、標準の生成器で layout.json と provenance を更新した。固定 Go 1.26.11 で静的イメージをもう一度生成して差分がないこと、元のコンストラクタと初期メモリの SHA-256 が一致すること、生成 Go の全ファイルの整合性を確認した。候補の通常ビルドで TestMatchedSemantics が通った。今回再生した範囲は固定の生成 Go からインストール後の候補までで、WASM の再翻訳は実施していない。[生成物照合](source-check.log) · [通常ビルドのSQL検査](smoke.log) · [再現手順](recipe/REPRODUCE.md)

## 計測条件

Apple M1、macOS arm64、Go 1.27.4、GOMAXPROCS=8。現行・分離それぞれ 4 プロセスを順序反転して測った。各プロセスで 8 fork に同一の注文データを入れて切断し、8 秒休止と同時復帰を 8 回、続いて 70.25〜73.25 秒の休止と同時復帰を 1 回行った。各波の初回 SQL は在庫の主キー読取 4 件と単一行の在庫更新 4 件。対象 DB は波ごとに反転する。各 DB の最終在庫、40 注文、100 明細、注文・明細の合計各 1,888,173 セントを照合した。予備試験は集計から除外した。[事前条件](protocol.md) · [全復帰要求](requests.csv) · [各試行](trials.csv)

P1 と P8 の参照値は前回の同一リングでの比較。分離案で P1 のスイート時間は現行比 −23.64%、P8 の 400 ms 以上の投入は 5/2,016 → 0/2,016 件だった。今回の検証は候補の再生成、短休止と同時復帰を対象にした。[P1・P8と単独復帰の固定レポート](https://github.com/masahitojp/mariamem/blob/df67fd52e03ea248ff94f4baefe1a3223cc6f273/benchmarks/pool-split-interval/results-20261121/README.md)
