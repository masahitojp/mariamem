# 生成 Go の JOIN 最適化は何に時間を使うか

**SUM 再集計の JOIN 最適化では、最も時間を使う大きな処理は統計作成（1.377 ms/100 INSERT）で、その中で毎回繰り返す処理として索引レンジ候補を評価する `get_key_scans_params`（0.494 ms）を特定した。** この関数には 1 INSERT あたり1回入り、4組とも親時間の 19.0〜19.6%（丸め前の最小 18.97%）を占めた。差分加算と明細 INSERT トリガーを外した対照では JOIN 最適化自体が0回だった。

Go shim の候補をさらに絞るなら、同関数内の計算と、関数表を介した下位呼び出しを区別することを推奨する。現時点の判断は **CRC と同様に Go へ移す処理を選ぶには証拠不足**。関数全体にはゲストメモリへの書き込み、arena 確保と複数の間接呼び出しがある。計測した 0.494 ms はそれらを含む経過時間で、単独で置換可能な計算に帰属する割合や実際の短縮量は未測定。[固定版の生成 Go](https://github.com/masahitojp/mariamem/blob/5a7ec57bba4c4021c0bc1d3f34f00eed892bf19c/internal/generatedgo/code/p2/p2_pure.go#L537234)

| 統計作成の残り（make_join_statistics） | 0.559 |
| JOIN 最適化の第2段階（optimize_stage2） | 0.714 |
| その他の最適化処理 | 0.490 |
| **JOIN 最適化全体** | **2.581** |

## どのように絞り込んだか

固定関数表 21,791 件と生成 Go の定義を照合し、9関数の呼び出し元と直接／間接呼び出しに計時点を置いた。幅広く計測した設定では親を含め静的な598箇所のうち112箇所に定常時の実行があり、各要求で排他的時間を合計した。最長の単一区間は4組とも test_quick_select からの get_key_scans_params 呼び出しで、平均 0.467 ms（0.459〜0.486）。同じ設定で make_join_readinfo は 0.167 ms、greedy_search は 0.133 ms だった。この設定では親時間が親のみの対応実行より +25.6〜+44.4% 延びたため、上の主表には4経路での再確認を用いた。

1段浅い設定では、最適化本体の make_join_statistics が 1.225 ms、第2段階が 0.713 ms、JOIN::build_explain が 0.141 ms、条件最適化が 0.121 ms。異なる計装での絶対値は揺れるが、統計作成が最大の大区分である順序は再現した。枝の inclusive はその配下を含み、exclusive は計装した子の外にある時間。未計装の子の時間は呼び出し元に含まれる。[全順位](ranked.csv) · [組別の排他的・累積時間と回数](edges-by-block.csv) · [全4モードの負荷対照](controls.csv) · [静的な対応表](edges.json)

## 判断の限界と再現

静的には get_key_scans_params に6箇所の関数表呼び出しがあり、直接の arena 確保もある。今回の計時境界はこの関数の入口と出口までで、各間接呼び出しが実際に選んだ転送先やその経過は未分離。次に試作可否を判断する材料は、この6箇所の動的回数・行き先・経過時間と、残る関数本体の時間。費用の目安は固定ベースの追加ビルド1回（上限20分）と同じ4組の対照再生1回（上限15分）。局所処理の入出力、メモリへの副作用、例外時の動作を保てるかの検証が、Go 側への置換試作の前提となる。

最終集計は主比較 60 プロセス・588 DB・58,800 INSERT、4経路の再確認 11 プロセス・99 DB・9,900 INSERT。注文合計、監査、在庫、制約、Close を確認し、計測した要求でフレーム・ID・時刻順・区間の和を再検証した。各 DB・各明細の共通計測点の回数は浅い設定と広い設定で一致。初回は対照の空チェック2回が合わせて 0 ns だった1要求を旧検査が拒否して停止した。初回試行を保存し、対照の 0 ns を許して全比較を最初からやり直した。報告値はすべて再実行と追加対照から算出した。[初回の記録](first-attempt/) · [主比較の検証](verification.json) · [追加対照の検証](focus-verification.json) · [環境](runs/environment.json) · [再現手順](recipe/REPRODUCE.md) · [チェックサム](SHA256SUMS)
