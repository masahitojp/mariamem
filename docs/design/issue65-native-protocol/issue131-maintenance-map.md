## Judgment and recommendation

**Next decision: authorize a small native-only split of the shared prepared overlay, preserving the embedded text metadata guard and the native conversion snapshot.** It targets a real upstream repair contact: the legacy parameter-metadata adapter's EOF insertion needed manual repair on13.0.2 although the native session does not call it. It is a better first reduction than moving queue/timer code, which mostly changes our own implementation location and leaves the MariaDB hooks intact. This task implements neither change nor architecture adoption.

The strongest opposing case is that native already works on13.0.2 with **zero new native C++ repairs**, so changing a working preparation profile can create more guard/binding/regression work than it saves. That is material: the proposed split is a reversible experiment whose benefit must be an eliminated native update obligation, not a shorter patch. Total update burden remains **INCONCLUSIVE**. Retain native as a viable candidate; this evidence establishes neither that it is cheaper nor that it is worse.

### Native conversion recovery is a separate retained internal dependency

`R:guest/experimental.patch:1634–1662` allocates one `Mariamem_wire_conversion` per parameter when new types are supplied, saves state **before** `setup_conversion_functions` and value insertion, then restores it and `sync_clones()` on rejection. `:1709–1746` copies type-handler pointers, value handler, unsigned flag, the **object representation of PValue_simple**, and `m_empty_string_is_null`. Copying representation avoids reading inactive union members; it does not make the snapshot insensitive to layout/ownership changes. `:1842–1858` separately validates every incoming descriptor before any conversion mutation so rejected descriptors preserve LONG_DATA.

Current callers are native prepared EXECUTE and its logged/nonlogged insertion functions, not mysql_stmt_bind_param. Retain guest ownership of statement map, conversion, pending LONG_DATA and rollback. On every upstream update, inspect **all mutations performed by setup_conversion_functions/setup_conversion/insert_params and string conversion, clone synchronization, ownership and reset_stmt_params**, against the saved fields and error paths. No direct C API caller is relevant to that proof. Header/TU relocation cannot eliminate it.

G1/G2 exercise rejected-then-reuse types, charset, NULL/signedness, malformed descriptors, surplus input and LONG_DATA; the small source-seam harness stubs Item/Handler and cannot prove completeness of the real union/ownership snapshot (`R:benchmarks/spikes/issue65-p1-timeout/check_source.py:1`). Full-file hashes detect upstream changes only after pins are intentionally reviewed; they do not prove semantic equivalence. #128's79/701 PASS and unchanged small binding constants are favorable finite evidence, not a layout theorem. Removing or redesigning the snapshot is **not** this task's proposed first change.
