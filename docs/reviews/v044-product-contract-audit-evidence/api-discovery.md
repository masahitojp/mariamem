# Current public-surface discovery — v0.4.4 Product Contract Audit

Read-only discovery baseline: `c8bd25a56e9d5221abaf40b2c98102bd60c217ae` (`main`). No production/documentation edits, runtime execution or new benchmarks. ## Evidence labels and limits

- **Demonstrated** below means repository consumer/integration tests or dogfood workloads exercise it. It does not prove an outside user requires the API.
- **Maintainer reliance:** `U` means unknown/unestablished, not “unused”. The session establishes prepare-once/Fork-many and disposable isolation as desired, arbitrary path writes as undesirable, and explicit read/import as acceptable. During this audit the maintainer explicitly confirmed **no intentional reliance on path writes/Destination, Snapshot.open, or class/session mutable sharing**: those APIs arrived with the originally imported concept. For those targeted rows, this confirmed answer supersedes any U/unknown qualification below. Other options/core APIs remain separately evaluated; do not generalize this answer into “no core user value.”
- Python lacks `__all__`; imported modules/functions are technically reachable. The inventory separates intended SDK/fixture surfaces from incidental names/private host control. It does not promote accidental reachability into a contract.
- Only seven pytest fixtures are defined. No fixture aliases, pytest command-line options, collection hooks, or magic automatic driver-connection fixture exist. Plugin loading is package entry point `python/setup.cfg:23`.
- There is no exported Go `Fresh`, `OpenSnapshot`, `Import`, runtime selector, `MaxSessions` option, SQL execution helper or connection-pool factory. Fresh means normal `Start`; users supply the MySQL driver/pool.

## Key code-vs-doc and cross-language contradictions

1. **Released v0.4.3 still described as pending candidate:** docs/go.md:13,40; docs/python.md:3,10,112; README.md:18,28; docs/project-status.md:112,163 use candidate/pending wording though maintainer says released. Main version constants are v0.4.3; current docs need status alignment, no runtime rebuild.
2. **Snapshot.open guest compatibility deferred:** docs/python.md:61 says manifests verify guest build compatibility. `snapshot.py:60` only accepts a syntactically well-formed SHA; `internal/host/server.go:74`/`internal/snapshot/snapshot.go:201` performs actual running guest equality during Fork. Acceptance `tests/snapshots.py:195` intentionally calls open then start for wrong-build rejection. Open is not complete compatibility validation today.
3. **Physical ownership != logical immutable template:** Go owns temp directory cleanup; Python open owns no external resource. Both still read externally mutable paths. Neither production model can claim owned exact verified backing; verification/use are separate path opens. `MapPreparedFiles` reopens after validation (`internal/generatedgo/code/base/prepared_files.go:33,47`).
4. **Go startup pin, Python no startup pin:** `snapshot.go:83` holds RLock through start; `snapshot.py:68,74` checks boolean then performs unlocked startup/removal. Python concurrent Close can remove temp during Fork validation/open/map. No claim this is observed test failure; structural gap established from code.
5. **Closed Snapshot alternate constructor bypass:** `Database(snapshot=s)` reopens path without checking original `_closed` (`__init__.py:63`); `s.fork()` checks closed. Explicit-destination closed handle remains usable through Database(snapshot=...). This is a real semantic asymmetry inside Python itself.
6. **Fixture mutable sharing is intentional in current code/docs but not established product need:** README.md:92 says “fixtures for independent databases”; plugin also supplies shared-class DB and mutable session server. docs/python.md:97 clarifies sharing but users must discover this. Consumer test actively carries schema from one test method to the next. Code evidence does not justify preserving it.
7. **Snapshot snapshot() consumes source**, unlike casual save-point reading of word Snapshot. Errors can consume source after acceptance, even with no returned Snapshot. Contract/docs must show this explicitly; host preconditions can accept idle open connections and forcibly close them, while recommended user workflow says close all clients first (`internal/host/server.go:217,249`). The latter is safe conservative guidance, not a false claim that every open connection is rejected.
8. **Error and metadata parity differ:** Go endpoint metadata after Close retained; Python errors. Go repeated Close returns stored error; Python subsequent Close returns None. Go errors.Is preserves standardized closed/unusable sentinels; Python mixes HostError, ValueError and filesystem/JSON errors at path boundary. This needs explicit alignment choice rather than silent assumptions.
9. **Current architecture does use OS page CoW:** `prepared_files.go:47` uses MAP_PRIVATE. No custom CoW filesystem/live-runtime clone is true but cannot be shortened to “no CoW.” This implementation detail belongs in architecture; public promise should be independent mutable children, not RSS guarantees.
10. **Historical override recommendations are actively misleading if read as current:** docs/v04-integration-audit.md:23 explicitly says NativeDir REQUIRED / do not remove; current nonempty NativeDir rejects. docs/go-zero-setup.md:93 says overrides supply path; docs/gorm-dogfood.md:196 still discusses NativeDir setup. Label/split history, not inferred current API requirements.
11. **Snapshot mismatch error category is not uniform:** docs/go.md:118 broadly associates manifest/hash/guest checks with artifact_mismatch. Current restore validation emits plain error (`internal/host/server.go:74`), which deferred wrapper turns into `host_start` / `host_setup` (`server.go:58`). Python malformed content often raises ValueError before spawning; guest mismatch reaches host_start later. Do not promise a stable shared artifact_mismatch exception category for all prepared input errors without alignment.

## Runtime/compatibility/host surfaces — bounded categorization

- `MARIAMEM_NATIVE_DIR` nonempty rejected in Go and Python. `MARIAMEM_RUNTIME` nonempty except generated-go rejected by Go API; Python wrapper/CLI does not consult it. **Cross-language environment asymmetry**, not a second Python runtime (`mariamem.go:123`, `_artifacts.py:50`, `cmd/mariamem-host/main.go:37`).
- `MARIAMEM_TIMING_DIR` enables opt-in instrumentation (`internal/timing/timing.go:21`, Python constructor:43), not a product capability; private tooling writes JSON paths. Do not require users to understand it.
- Host command `mariamem-host --snapshot path --query-timeout 30s --startup-timeout 120s --shutdown-timeout 30s` exists (`cmd/mariamem-host/main.go:37`) plus stdin JSON `status/close/snapshot`. It is packaged SDK machinery, **not documented standalone user CLI**. `--snapshot` is an additional actual external read surface. Owner stdin EOF/signals trigger child runtime shutdown; successful Snapshot ends process. Flags/control protocol need internal compatibility for wrapper, not first-class product concepts.
- Wire protocol: local TCP4, multiple independent client sessions, advertised capacity currently16; recoverable MySQL1040 on excess; no one-connection pool workaround required; user SQL commit/rollback real; text query/interpolation supported, server-side prepared statements unsupported. Session count is current guest behavior, not exported option/permanent promise (`docs/go.md:71`, `internal/host/server.go:99`, README.md:163).
- Active-query client cancellation/disconnect or host query timeout invalidates **whole DB**; idle disconnect and ordinary SQL error leave DB usable. Go Start context is startup-only; Python has no async cancellation token/API. This differs from conventional client expectation “cancel query but keep DB.” Known hard-failure containment limitation remains; cannot be fixed by API audit (`docs/go.md:81`, docs/python.md:115).
- Incidental reachable Python names: `ArtifactError` imported from private module, `digest`, `inventory` under snapshot module, imported modules/PYTHON_VERSION. No user guide or outside requirement establishes them as intended API. Add explicit API export boundary later if justified; do not invent tests/public concepts to preserve incidental names.

## Representative real evidence and absent evidence

Present: lightweight CRUD/defaults; independent child state; template fixtures seeded/migrated once; transactions/constraint/protocol/auth/session behavior; SQLAlchemy repeated fork suite (`tests/consumer/test_sqlalchemy_dogfood.py:137`); GORM migrations/AutoMigrate dogfood; actual pytest-xdist fixture acceptance; external persistent reopen and corruption **acceptance tests**.

Not established: cross-process CI Snapshot cache used by an application, persistent Snapshot as sole production test-fixture source, external user reliance on class mutable-state sharing, snapshot destination for disk placement pressure, debug state export requirement, outside user custom host deployment. User says sole consumer is maintainer; compatibility urgency must not be inferred from API/tests alone. **Audit clarification additionally confirms no intentional maintainer reliance on the path write/import and class/session mutable-sharing APIs.**

Important distinction: path/reopen regression coverage proves implementation behavior and migration cost, not that permanent core save/reopen semantics are needed. Likewise the TestShared acceptance test proves mutable sharing works, not that this is the intended product isolation policy.
