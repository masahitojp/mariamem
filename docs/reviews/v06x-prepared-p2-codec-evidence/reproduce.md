# P2 initial codec component

This is an intermediate implementation checkpoint on `experiment/prepared-product`,
not a completed P2 gate or a main-adoption request. The full approved P1–P6 scope
is unchanged. `receipt.json` binds exact authored/test inputs; `codec-tests.txt`
and `fuzz.txt` retain local results. The two P1 runtime JSONs are the original
successful CI artifacts from3496095; previous failing artifacts remain separate.

## Component tests

Use pinned Go1.26.8:

```sh
python3 scripts/git_identity.py inspect HEAD
go test -race -count=1 -v ./internal/preparedproto
go test -race -count=1 ./internal/preparedproto -run '^$' \
  -fuzz FuzzExecuteAndInternalValues -fuzztime 15s -parallel 2
```

The codec is not called by Serve yet. These tests do not execute a generated
guest. The native-row tests use saved independent server output, including
FLOAT negative-zero canonicalization, not expected values generated by the
codec under test. The fuzz count is diagnostic and will vary.

## Native reference

Create a disposable MariaDB12.3.3 reference with no persistent volumes:

```sh
docker run --rm --detach --name mariamem-prepared-p2-native \
  -p 127.0.0.1::3306 \
  -e MARIADB_ALLOW_EMPTY_ROOT_PASSWORD=1 -e MARIADB_DATABASE=test \
  mariadb@sha256:805c8e104bd563d5bfa24fadd3f31cd419ea859cb5277f32b5dbf2db714f9ed1
docker port mariamem-prepared-p2-native 3306
```

Wait for that server to accept connections. In a disposable Python environment
with PyMySQL1.2.3 installed, substitute its localhost port below:

```sh
python tests/v06_prepared_p2_probe.py --native-port PORT \
  --reference tests/fixtures/prepared-p2-native.json --output /tmp/p2-native-replay.json
docker stop mariamem-prepared-p2-native
```

Do not overwrite the native fixture to make a guest comparison pass. The saved
reference is Linux arm64 on Docker Desktop/macOS; it does not establish Ubuntu
x86_64 or macOS-native server execution. SQL mode is empty and timezone+00:00
explicitly, with utf8mb4_general_ci. A15-second fuzz run or native-only replay
does not establish guest/API equivalence, malformed-input native parity, engine
allocation recovery, temporal range behavior or prepared CALL result chains.

The probe's optional `--host` mode is for later P2 integration. It is **not run**
against the current P1-only guest; its EXECUTE operation remains unimplemented.

## Ownership and next implementation

Internal payload: little-endian u32 parameter count, then repeated u8 type,
u8 flags(bit0 unsigned,bit1 NULL), u16 zero, u32 byte length and exact bytes.
Fixed numeric values have their requested width. Temporal bytes exclude their
one-byte wire length; length-encoded string/blob/decimal bytes exclude their
length prefix. NULL has zero length; empty non-NULL values remain non-NULL.
The full request additionally uses the existing16-byte PS envelope.

The next guest binding must independently check every count/length/type against
the owning MYSQL_STMT, create aligned native numeric/MYSQL_TIME buffers, and
retain no borrowed request pointers after their lifetime. Fetching must return
engine-produced typed values and recover complete variable-length fields through
fetch_column. The host then validates current metadata and emits binary rows.
Special parameter-code conversions require explicit native/API checks; result
column widths cannot by themselves establish parameter binding semantics.
There is no new capacity cap and no LONG_DATA implementation in this component.
